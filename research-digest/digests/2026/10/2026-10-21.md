### 🔥 今日必看

- **[RFC] Programmable KV Cache: Composable Policies for Agentic Serving**（SGLang issue #45189，2026-10-19 开，open）— https://github.com/sgl-project/sglang/issues/45189
  复用 `KvHintsEnvelope`：一条消息带若干 action（SET_PRIORITY / COPY_TO / MOVE_TO），目标可以是"已提交请求内容""session 内某 branch 的 token range""显式内容 ID"；优先级是带 revision 和有限时长的 claim，有效优先级取各 claim 最大值。不暴露物理地址 / allocator block ID。task 完成时回收该 task 的 association 与 policy 声明，但保留仍被其他 task / 活跃请求引用的内容；token range 解析会如实报告覆盖缺口，不静默扩展。
  对 StructKV 的意义：**P3**（协议与 SGLang 执行）+ 接口边界调研（"StructKV 插入点"）。这是 SGLang 侧第二份相关 RFC（另有 #24656 Phase 1），token range 作为一等目标，正好能承载 episode → span 的映射；但它**没有**定义 message / tool-call / episode 边界 schema（只用 workload 信号让策略自行解释），**没有**内容级 prune / in-place edit，**没有**公开 position reindex（树分裂 / 合并只讨论 claim 过期的保持）。即：它是"保留 / 驱逐优先级"通道，不是"删除 + 重索引"通道；P1/P3 的 prune+reindex 原语在 SGLang 接口层仍是空白，可作为 P3 协议设计的直接对照与扩展点。

### 📊 Workload 与证据

- **Adaptive KV Retention for LLM Agents at Human-Approval Timescales**（arXiv 2608.30830）— https://arxiv.org/abs/2608.30830
  针对分钟到小时级的人工审批停顿（对比 Continuum / MORI 的秒级工具停顿），把保留 / 卸载 / 丢弃 KV 的代价记为"GPU 机会成本"，按等待时间分布选择主机内存保留或负载相关的过期时间。仅见摘要级信息，未读全文。
  对 StructKV 的意义：**E1/动机侧**——补充"agent 停顿期间 KV 保留 vs 重新 prefill"的代价口径；属纯保留策略，不涉及结构信号驱动的剪枝，与 TraceLab / Copilot traces 的"人类节奏间隔"发现互证。
