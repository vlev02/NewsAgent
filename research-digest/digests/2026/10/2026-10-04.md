### 🔥 今日必看

- **From Research Paper to Real Workload: KV-Cache Editing with the LMCache SDK**（LMCache blog，2026-09-07，此前未收录；仅见搜索摘要）— LMCache 提供面向 KV 编辑研究的 SDK：prefill / decode 留在 GPU，KV cache 落在 host 侧被编辑，编辑函数不在推理热路径里运行，只需一个 Jupyter notebook 即可把 KV 编辑研究接到真实 workload 上。
  - 对 StructKV 的意义：**P3（协议与 SGLang 执行）**——这是引擎侧"原地编辑执行层"的现成原语 / 接口候选，P3 需要对照它的编辑操作集（是否含 delete + position reindex）和调用入口，判断是复用还是自建；同时见下方竞品预警。

### ⚠️ 竞品预警

- **LMCache SDK KV 编辑博客（2026-09-07）— 疑似核心竞品 Models Take Notes at Prefill（2606.17107）的 follow-up，关联未核实**
  - 重叠点：服务侧的 KV 原地编辑（splice / 重定位）接口，与 StructKV 的 P3 执行侧直接相邻；2606.17107 本身报告 position-portable 的 KV 注释可 RoPE 重定位后拼接，无需 re-prefill。
  - StructKV 的差异：从摘要看，SDK 提供的是"编辑执行"通道，没有看到由 agent 结构状态（episode 边界、失败 / 重试 / 覆盖标记、依赖图）自动生成编辑决策的部分，P2 的决策算法（E1 / E2 / E3）与 P1 的 prune+reindex 安全性论证仍未被覆盖。需读全文确认是否内置 reindex 与决策接口。
- 核心竞品其余成员（Leyline、IntentKV、MemDecay、CWL、TokenPilot、CodeComp、SmoothAgent、Stateful Inference、SideQuest）：按名称和 arXiv ID 逐一搜索，未见新版本或新 follow-up（TokenPilot 最新修订为 2026-08-28，不在窗口内）。

### 📊 Workload 与证据

- **Persistent Context Graphs for Efficient Memory Compaction in LLM Agents（ReCAP）**（arXiv 2609.40118，2026-09-30，此前未收录）— 把注意力导出的消息重要性和依赖链接存进轻量持久化 context graph，每次请求结合相关性并沿依赖链选出消息及其支撑上下文，无需额外模型调用；相对 Codex 默认摘要式 compaction，compaction 与冷恢复估计延迟降约 95%，SWE-Together 上每次调用的历史上下文约减半，质量相当。代码：UCSB-NLP-Chang/ReCAP。
  - 对 StructKV 的意义：**P2（依赖图信号来源 / E1 对照）**——符合 deprioritize_exceptions 的"依赖图信号"例外；执行仍是文本层选消息后重发（不在 KV 层原地编辑），不构成竞品，但其"依赖链保活"可作为 StructKV 依赖图信号的文本层 baseline。
- **When Fancy Eviction Fails: Rethinking Cache Replacement For LLM Prefix Reuse**（arXiv 2609.28870，2026-09 下旬，此前未收录；仅见摘要）— 在 agentic workload 下考察 prefix cache 的替换策略，复杂 eviction 策略收益有限。
  - 对 StructKV 的意义：**P2 E1 动机**——可作为"通用 LRU / 复杂策略对 agent 负载无效、需要结构信号"的机理证据。
