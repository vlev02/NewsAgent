### ⚠️ 竞品预警

- **TokenPilot: Cache-Efficient Context Management for LLM Agents**（arXiv 2606.17016，已收录竞品；本次为状态更新，非新版本）— 搜索命中一篇 10-13 的第三方转述（besthub，未能抓取原文）：称 TokenPilot 被 EMNLP 2026 接收，在 Claw-Eval 上成本最多降 87%，并已集成 6 个 coding agent。arXiv 原文未见 v2，技术内容是否有变化未核实。
  - 重叠点：以 cache-hit / cache-miss token 计价来做 agent 上下文管理，与 StructKV 的动机侧（re-prefill 代价）重合。
  - StructKV 剩余差异：TokenPilot 在文本层决策并重发上下文，不在 KV 层做 prune + reindex（P1 无重叠），也没有结构信号到 KV 指令的翻译（P2）和 SGLang 原地执行（P3）；"已集成 6 个 agent"说明其落地面更广，P3 评估时需对比其集成成本。
  - 对 StructKV 的意义：P2 E1 的文本层 baseline 与 related work；严重度低，仅提示关注其正式版本。

### 📊 Workload 与证据

- **AA-AgentPerf（Artificial Analysis 硬件 benchmark）**— 回放真实 coding agent 轨迹，覆盖长上下文、工具调用延迟与可观的 KV 复用机会；发布日期未核实，仅依据搜索摘要。
  - 对 StructKV 的意义：P2 E1 评测负载候选；是否带 message / tool-call 结构标注未核实。
- **Benchmarking LMCache for Multi-Turn Agentic Workloads on AMD MI300X**（LMCache blog，2026-05-12，旧文首次收录）— 用 739 条匿名 Claude Code 轨迹（kv-cache-tester）对比无缓存、vLLM HBM prefix cache 与 LMCache CPU-DRAM offload：高压下 LMCache 延迟和吞吐占优，低负载时 HBM prefix cache 更好。仅依据搜索摘要。
  - 对 StructKV 的意义：P2 E1 动机数据——整块 offload / prefix 复用的收益随负载翻转，说明粗粒度 cache 管理有上限；轨迹来源可用于核对 episode 切分。

### 📦 Baseline 动态

- **SemantiCache**（arXiv 2603.14303，2026-03，旧文首次收录）— 按自然语言分隔符做语义分块，块内聚类合并，分隔符条目保留作锚点；满足 tier_3 (c) 的 chunk 级机制，但仅见摘要，未见 agent 评测。
