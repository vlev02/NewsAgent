### 🔥 今日必看

- **Capture the lifecycle: KV Cache management in ReAct Agents with KVTether**（arXiv 2609.39819，约 10/1-10/2 挂出，提交日期未能核实；依据搜索摘要，未读全文）— 指出 agent harness 与 serving 栈之间存在语义鸿沟：context message 在 context 变更、工具执行、subagent 协作中会变成"活跃 / 永久丢弃 / 暂时闲置"，而 serving 栈只看得到 KV 的访问。KVTether 追踪 harness 里的语义原语，把 message 级语义翻译成 KV 级生命周期状态，据此做状态优先的缓存管理：先回收逻辑已死的 "zombie KV"（如 compaction 之后被替换掉的旧历史），再优先保留"活着但闲置"的 KV；报告 LRU 驱逐中 71.0–95.0% 是方向错误的。
  - 对 StructKV 的意义：**P2（E1 有效性、E2 分歧率）+ 接口边界调研（ID 在哪层丢失、StructKV 插入点）**——它正是"message 级结构语义 → KV 层决策"的同类工作，也直接回答"语义在 harness→serving 边界如何翻译"。同时见下方竞品预警。

### ⚠️ 竞品预警

- **KVTether（2609.39819）**
  - 重叠点：用 agent 结构语义（message 生命周期：活跃 / 丢弃 / 闲置）驱动 KV 层的保留与回收决策，且不走文本重发；与 StructKV 的"结构信号 → KV 决策"主张在 P2 信号侧直接重叠。
  - StructKV 还剩的差异：（1）从摘要看，KVTether 的动作是整条 KV 的回收 / 优先级排序，而不是 prune 之后对留存 KV 做 position reindex，P1（ReClaim 的 prune+reindex 安全性）没有重叠；（2）没有看到 episode 边界、依赖图或覆盖 / 重试 / 失败标记的建模，E2 分歧率与 E3 消融仍可占位；（3）没有看到跨层协议和 SGLang 侧的原地编辑执行（P3）。以上均基于摘要，需要读全文确认其是否也做了物理位置压缩。

### 🔗 Agent ↔ Serving 接口

- **KVTether（2609.39819）**— 见上。"semantic primitives in harness → KV lifecycle state" 是一条具体的 harness→serving 通路设计，说明 harness 侧可观测的信号并不需要暴露物理 KV 复杂度。
  - 对 StructKV 的意义：**接口边界调研：StructKV 插入点**——可对照它的原语集合，核对 StructKV 需要的 episode / 工具调用状态是否已被覆盖，以及信号是在 harness 内部翻译还是跨进程传递。
- **A Policy-Driven Runtime Layer for Agentic LLM Serving**（arXiv 2605.27744，2026-05，旧文，此前仅记备查，本次补收；仅见摘要）— 在 agent 框架与 serving 引擎之间引入第三层 agent runtime，持有两侧都没有的跨层 agent 元数据，由它做 agent 级策略决策。
  - 对 StructKV 的意义：**接口边界调研：Episode 表达放在哪一层**——又一个"元数据应该驻留在中间层"的数据点，与 SGLang #24656 的引擎内部元数据路线形成对照；是否包含 KV 编辑动作未核实。

### 📊 Workload 与证据

- **vLLM x AgentX: Optimizing for Real-World Agentic Serving**（vLLM blog，2026-09-08，此前未收录；依据搜索摘要，页面无法抓取）— 基于 SemiAnalysis AgentX（约 $3M 真实 coding agent trace 的开源多轮 benchmark）：会话中位数 43 轮，输入中位数 142K token、输出中位数 444 token，prefix cache 命中率 96% 以上；围绕 KV 管理、长上下文并行、PD 分离做优化。
  - 对 StructKV 的意义：**P2 E1 / 动机**——提供"长上下文、极短输出、命中率已很高"的 agentic 负载量级，可作为 StructKV 评测负载与动机数据；该 benchmark 是否带 message / tool-call 结构标注未核实。
