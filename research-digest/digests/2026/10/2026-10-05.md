### 🔥 今日必看

- **[RFC] Programmatic Session-Aware KV Cache Management**（vLLM issue #51428，2026-08-07 开，仍 open，此前未收录；正文已核实）— 提出面向 router / orchestrator 的窄接口 `KvHint{target(逻辑 KV block), action ∈ Share/Prefetch/Demote/Pin/Retain, bounds(TTL/priority/destination)}`，原则是"orchestrator 拥有策略，engine 负责执行"，hint 为软约束，engine 可接受、裁剪、延后或拒绝。动作集只覆盖保留 / 优先级 / 分层迁移，不含 span 删除、splice、reindex。
  - 对 StructKV 的意义：**P3 + 接口边界调研（StructKV 插入点）**——给出了"策略在引擎之外、引擎只执行 block 级指令"的分工和 target = 逻辑 KV block 的寻址方式，StructKV 的 episode → token span / block 映射可以直接对接这一寻址；缺口正是编辑类动作（delete + position reindex），即 P1/P3 要补的 directive 类型。需注意它是软 hint，而 prune+reindex 会改变后续 token 的位置语义，不能被"拒绝"后静默降级，协议里要定义失败语义。

### 🔗 Agent ↔ Serving 接口

- **[RFC] Agent-Aware KV Cache Affinity Scheduling and Lifecycle Management**（Kthena issue #1828 / AIBrix issue #2814，均 2026-09-25 开，仍 open，此前未收录；正文已核实。llm-d issue #2584 标题相同，未抓取）— 两个下游栈同步提出：经 router / sidecar / Mooncake 传递标准化元数据 `program_id / priority / context_type(system_prompt, tool_def, conversation, reasoning) / session_ttl_hint`，按 context_type 加权驱逐，`open / heartbeat / close` 会话生命周期信号固定缓存，外加投机 prefill。均明确不含 KV 编辑 / 剪枝。
  - 对 StructKV 的意义：**接口边界调研：ID 在哪层丢失 / Episode 表达**——`context_type` 是目前最接近"结构类型标签跨层传递"的工业提案，但粒度只有 4 类静态角色，没有 episode 边界、失败 / 覆盖 / 重试标记或依赖边；可作为 StructKV 信号 schema 对比的参照（与 SGLang #24656、v0.5.21 session_id 合看：元数据通路在加宽，编辑原语仍缺失）。
- **Parallel Context Compaction for Long-Horizon LLM Agent Serving**（arXiv 2605.23296，2026-05，此前未收录；仅见标题与搜索摘要，是否在 KV 层执行未核实）— 面向长程 agent serving 的并行 context compaction。
  - 对 StructKV 的意义：**P2 E1 文本层对照 / 动机（re-prefill 代价）**——属 SmoothAgent 一脉的"compaction 触发重算"问题，需读全文确认是否暴露可被 KV 层消费的信号；价值待定。
