### 🔥 今日必看

- **TwinKV: A Composable Repair Pass for KV Cache Eviction via Pairwise Key
  Redundancy**（arXiv 2608.27128，Hong Chen / Yudong Zeng / Yongwei Huang /
  Zuhao Ouyang / Junyan Zhang / Xuming Hu，8/27 挂出）— 提出训练无关、不依赖
  attention 分数的 pairwise key 冗余信号：检测某个 token 的 key 在上下文其他
  位置是否存在近似重复（"twin"），并以此识别被错误淘汰且无冗余副本的
  "孤儿" token，与被冗余保留却仍占预算的 token，两者互换以修正已有 eviction
  策略（H2O/SnapKV 式打分）的分配结果——定位为可叠加在任意现有 eviction
  策略之上的 repair pass，而非又一个独立打分方法。论文明确主张 attention
  幅度与 token 对答案的因果贡献"无关"，直接挑战主流打分式 eviction
  （H2O/SnapKV/ChunkKV 一脉）的核心假设。与本轮此前收录的 **Trust the Mass**
  （2608.25230，8/25，主张直接保留权重最大的 key 已接近最优，性能差距主要来自
  实现层面而非打分算法）构成同一周内对"eviction 打分基础是否可信"这一问题的
  又一个数据点，但结论方向相反：TwinKV 否定 attention 幅度作为重要性代理的
  有效性，Trust the Mass 则认为简单权重排序已经足够——两篇论文对同一个问题
  给出了相反判断，值得后续交叉核实谁的实证设置更站得住脚。三路独立检索
  （tier_0/tier_1/watchlist）均确认该 arXiv ID、标题、作者列表一致；受环境
  egress 限制未能直接访问 arXiv 摘要页，细节以搜索引擎摘要为准。

### 🏗️ 工程/生态动态

- **vLLM**：发布 **v0.28.0**（8/26），是一次分量很重的 KV cache 相关更新：
  磁盘 offloading 支持；可通过 `module_path` 接入 out-of-tree 的二级存储
  管理器；partial secondary-tier load 结果；tiering 指标；面向并行策略无关的
  canonical CPU offload 布局；Mamba 模型默认开启 prefix caching；细粒度
  partial-tail prefix 复用；E/P/D disaggregation（Model Runner V2）；权重
  offloading；multi-layer MTP KV cache 支持；KV cache 布局重构下的
  backend-published KV packing；关闭 prefix caching 时恢复 LIFO 空闲块复用
  顺序；MLA chunked context 的 per-request 调度；长上下文 MLA cache gather
  优化。另有一篇 Medium 技术博客（Achyuthan Sivasankar，"When Memory Layout
  Assumptions Collide"）记录了 `OffloadingConnector`（KV offload）与
  per-token-head KV 量化组合时的布局假设冲突 bug（前者假设跨层交错缓冲区，
  后者假设逐层连续缓冲区），是一篇调试记录而非新技术，仅作背景记录。
- **LMCache**：最新 pre-release 仍是 **v0.5.5rc1**（8/28），核实 changelog
  后确认唯一改动是给 `lmcache bench engine` 增加 `--no-warmup` 命令行参数，
  纯测试工具类改动，不计入实质性更新（与 8/28 digest 结论一致）。另发现
  AMD ROCm 官方博客"4-bit KV Caching in LMCache: Offloading Quantized KV
  Beyond HBM for Context-Heavy Agents on AMD MI355X"（约 8/28），介绍在
  MI355X 硬件上通过 LMCache 做 4-bit 量化 + 分层 KV cache offload（HBM →
  CPU DRAM），偏硬件适配/工程实践记录，非新算法。
