### 🔥 今日必看

- **Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for
  Prefill Reuse**（arXiv 2608.03893，Taekyung Heo 等，8/4 挂出）— 把"KV cache 复用"
  从同模型跨请求/跨轮次，推广到同一模型家族内跨模型尺寸（cost-quality cascading、
  mid-conversation switching、routing 场景下模型切换需要重新 prefill 的问题）：发现
  匹配 KV head 数/per-head 维度的源模型-目标模型对之间，KV 存在显著线性结构，据此
  设计逐 head 的闭式 ridge mapper（500 条 FineWeb-Edu 校准序列拟合），接收方直接用
  映射后的源模型 KV 跳过 prefill。三个模型家族六对模型中四对能保住 73-98% 的
  standalone-prefill 精度，映射本身比重新 prefill 快 2.7-25x，多轮 handoff 下稳定。
  这是本追踪首次遇到"KV 可跨模型尺寸线性迁移"的具体证据，与已收录的 Prefill-as-
  a-Service（跨数据中心迁移同模型 KV）、AgentKVShift（跨轮次同模型 KV 复用残差）
  构成 KV 复用问题的第三个维度——不是"何时/何地复用同一份 KV"，而是"能不能把 KV
  本身搬到另一个模型上用"，对 R1（多块 re-index 是否 scramble 位置编码）没有直接
  交集，但为"KV cache 的可迁移边界到底在哪"这条问题线新增了一个强信号。

#### Systems / Serving

- **Preserving Admission Responsibility in Multi-Tenant Large Language Model
  Prefix Caches**（arXiv 2608.01657，Zhiyu Wang / Rajkumar Buyya，8/3 挂出）—
  指出共享 prefix cache 场景下存在"admission-responsibility gap"：某个租户新
  写入的 KV block 可能挤占其他租户可复用的状态，但现有 request-time 调度器只算
  瞬时服务量、替换策略只按对象价值排序、静态分区又会闲置容量，三者都没有把
  "谁造成了驱逐责任"计入决策。提出 PrefixShield：对新写入的完整 KV block 计量、
  让责任跨请求累积（carry debt across requests）、debt 未清前 gate 掉 reuse
  promotion、用 projected debt 决定由哪个租户组提供驱逐候选，在 vLLM 中实现。
  与已收录的 PrefixWall（缓解 prefix cache 侧信道泄露）构成多租户 prefix cache
  问题的两个不同切面——一个管安全隔离，一个管公平驱逐——但都落在"共享 KV 状态
  该如何在租户间治理"这条系统层问题上；tier_1 watchlist（vLLM KV cache）新收录。
