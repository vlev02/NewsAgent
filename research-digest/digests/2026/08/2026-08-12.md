### 🏗️ 工程/生态动态

- **待跟进项核实（来自 8/11 digest）**：SGLang `v0.5.17` release 标题中的
  "session-reference-aware caching"，本轮核实为 `--enable-session-radix-cache`
  （PR #29173）——面向 agentic/RL-rollout workload，请求携带 stable `session_id`，
  radix cache 的驱逐决策据此感知哪些 prefix 仍被活跃 session 引用（而非纯按 cache
  policy 驱逐），引用通过 `/close_session` 释放。该被动 session-aware radix
  ownership 能力实际在 SGLang `0.5.15` 就已支持，`v0.5.17` release note 只是把它
  作为亮点重新提及，并非本轮新增特性。与已收录的 PrefixShield（多租户 prefix
  cache admission-responsibility）构成同一"把 agent/session 语义暴露给 KV cache
  驱逐决策"主题下的两个实现路径。
- **vLLM**：未检索到超出 8/11 记录的 `v0.27.1` 的新版本（`v0.27.2`/`v0.28.0`
  均未发布）。
- **SGLang**：未检索到超出 8/11 记录的 `v0.5.17` 的新版本。
- **LMCache**：未检索到超出 8/10 digest 记录的 `v0.5.3`（8/5）的新版本。
- watchlist 逐一核实：SnapKV/ChunkKV/H2O/CacheBlend/CacheClip/SideQuest/
  IntentKV/MiniPIC/MEPIC/CacheSlide/Attention Matching KV/Parrot/Preble/
  Autellix/InferCept 均未发现超出已知版本的新论文/release。
