### 🔥 今日必看

- **PatchKV: Efficient KV Cache Recovery for Dynamically Edited LLM Contexts**（arXiv 2609.26219，
  天津大学）— 长程 agent 会话中途编辑上下文的某个内部 span、保留长后缀时，后缀 token 虽未变但
  causal 历史和 RoPE 位置已变，无法直接复用其 offload 的 KV。PatchKV 把上下文版本分解成"不可变
  前缀 / 被编辑 span / 位置对齐后缀"三段，用离线长度条件漂移模型预测编辑局部的"脏区"，叠加从已存
  attention 中挑出的稀疏非局部块构成修复集；其余后缀块用冻结的逐块精度标签，走"反量化 + RoPE
  校正 + KV 页放置"融合路径从 CPU 直接恢复，不重算。相比全量重新 prefill 实现 2.51–3.85 倍 TTFT
  加速。
  **对 StructKV 的意义**：直接落在 P1（ReClaim，prune+reindex 原地安全性）——这是目前收录到的、
  执行侧与 StructKV 最同构的一篇：RoPE 校正 + 原地页恢复，明确不走文本重发。但它的"脏区"判定靠
  通用编辑 diff 模型，不是显式的 episode 边界 / 工具调用状态 / 依赖图等 agent 结构信号，P2（结构
  信号→决策算法）侧仍是空白，这正是 StructKV 需要补上的差异化贡献；同时它与已收录的
  Contiguity, Not Importance（2609.17983）构成同一问题簇下机制高度重叠的两个独立实现，值得放在
  一起精读，判断 StructKV 的 reindex 安全性证明相对这两者能提供什么增量。

### ⚠️ 竞品预警

- **PatchKV**（同上，详情见"今日必看"）— **重叠点**：执行原语与 StructKV 高度同构——原地
  RoPE 位置校正 + 页级放置恢复，不经过文本重发，直接服务"prune+reindex 是否安全"这一核心问题。
  **StructKV 差异还剩什么**：PatchKV 的"该修哪里"由通用文档编辑 diff（离线漂移模型）决定，而非
  由 agent 暴露的结构 / 语义状态（episode 类型、工具调用生命周期、失败 / 覆盖标记、依赖图）决定；
  StructKV 的空间在于把"结构信号→具体决策"这条链路做实（P2），并证明其 reindex 操作在显式结构
  驱动、而非通用 diff 驱动场景下的正确性边界（P1）。建议后续动作项：读全文核实其漂移模型能否
  直接吃 agent 结构信号作为先验，如果可以，二者的差异会进一步收窄。

### 🔗 Agent ↔ Serving 接口

- **SGLang PR #37482 "feat(agent sessions): attribute stored KV cache blocks to sessions"**（已
  合并，2026-09-14）— 是已跟踪的 SGLang RFC 链条（#24656 → #27574）在代码层面的实际落地：radix
  cache 存储的 KV block 现在携带 session 归属信息，供 `agent_hints` 驱逐策略消费。**对 StructKV
  的意义**：把"ID 在哪层丢失"这条调研线从纯 RFC 讨论推进到已合并代码——目前落地的粒度仍是
  session 级，不是 episode/tool-call 子粒度，量化了 P3 执行层当前的真实工程进度基线。
- **Architecting Conversational Data Systems for Stateless LLM APIs: The Hydration Proxy
  Pattern**（arXiv 2609.01834，Joseph Axisa / Google Cloud，ACM CAIS 2026 SAO workshop）— 提出
  三层架构把会话状态持久化与无状态推理引擎解耦，并提出"Context Stabilization Mandate"试图调和
  "平台自主管理会话状态"与"基础设施层 KV 缓存复用"之间的张力。**对 StructKV 的意义**：是接口
  边界调研中"Episode 表达应该放在哪一层"问题的又一数据点——这次的答案是"放在推理引擎之上的独立
  会话持久化代理层"，与 vLLM/SGLang RFC 们"把结构信号往下沉到 engine 内部"的方向相反，P3 协议
  设计时值得对比这两种分层哲学各自的取舍（工程可落地性 vs. 语义粒度）。
- **UNISON: A Co-Designed Near-Memory Scheduler of Session KV Residency for LLM Agents**（arXiv
  2609.09643，Fan He/Yan Li/Xiaoyang Zeng，复旦大学）— 把"return-gap"（工具调用等待间隙）作为
  会话级一等信号，用 gap 指数滑动平均 + 按轮次索引的完成风险两个运行时可观测量驱动近内存驻留/
  分层调度（SPEAR + TIDE），而非用 recency/timeout/identity 代理信号。**对 StructKV 的意义**：
  是"agent 执行结构信号驱动 KV 层决策"这一命题在硬件层面的新实例，与 StructKV 在 serving 软件层
  的 prune+reindex 主张构成同一问题在不同系统层级的呼应——如果工具调用等待这一结构信号值得在硬件
  层专门建模，serving 软件接口设计也应该把它当作一等公民传递，而不只是当前 PR #37482 那种
  session_id 级粗粒度标识。

### 📊 Workload 与证据

- **Nexus: Depth-Adaptive KV-Cache Splicing and Retrieval-Decoupled Tool Routing for Agentic
  LLMs on Unified Memory**（arXiv 2608.20397，Mustafa Arslan，ICML 2026 Workshop FAGEN）— 面向
  MCP 工具密集型 agent，主张对工具 registry 做 off-anchor KV 拼接从根本上受 RoPE 相位漂移限制，
  转而把工具路由与 schema-prefill 成本彻底解耦：INT8 语义旁路缓冲区做检索式路由，参数生成走压缩
  文本 signature 而非拼接 KV；250 工具规模下路由准确率仍约 89%，首个参数 token 比全 schema 重新
  prefill 早到 1.66 倍。**对 StructKV 的意义**：是关于"KV 拼接类原语在何处失效"的重要负面证据，
  对 P1（ReClaim）在工具调用场景下的适用边界有参考价值——提示 RoPE 相位漂移可能是拼接类执行原语
  的通用风险点，而不只是 StructKV 需要单独面对的问题，需要在 P1 的安全性论证里正面处理这一点。
- **CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents**（arXiv
  2609.26779，Trang Nguyen/Eulrang Cho/Bingqing Chen(Bosch)/Tim Dettmers(CMU)，9/22 挂出）— 长程
  coding agent 会话压缩若朴素滑动上下文会使 prefix-cache KV 状态失效、迫使昂贵重新 prefill（"压缩
  悬崖"，承接已收录的 2608.16370 / 2608.22752）；CliffCompaction 只截断/丢弃整轮、绝不改写/重述
  已有轮次，明确以此保护 prefix cache 不被打散，在有界上下文预算下降低最多 50% token 成本，
  Terminal-Bench/KernelBench 上持平或提升，已与 Claude Code/Codex 集成开源发布。**对 StructKV
  的意义**：机制仍在文本层，但满足 deprioritize_exceptions 中"明确测量/讨论对 prefix cache 命中率/
  re-prefill 代价的影响"这一例外条款，是 P2 E1（有效性实验）可参考的"什么样的文本层策略对 KV 层
  友好"的正面数据点，也是"only drop, never rewrite"这条设计原则与 StructKV 剪枝（而非改写）主张
  的又一次独立印证。
