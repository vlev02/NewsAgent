### 🔥 今日必看

- **BeaconKV: Key-Value Cache Compression Guided by Beacon Queries for Efficient Large Reasoning Model
  Inference**（arXiv 2609.04971，Hanyang University/Sungkyunkwan University）— 现有KV cache压缩方法
  （SnapKV/H2O一脉）普遍依赖"近期查询预测未来token重要性"这一假设，但大型推理模型（LRM）生成长链式思考
  （CoT）时存在Thought Revisiting Token（TRT）——某些解码步会重新关注早先制定的任务求解计划等远距离
  上下文，直接使该假设失效；提出训练无关的beacon query引导压缩，识别并保留会被TRT重新关注的远距离KV；
  是tier_0核心假设在"推理模型长CoT"这一增长中的新场景下的反例，代码已开源（aiha-lab/BeaconKV），
  实践价值高。

- **It's Not RoPE that Creates Sinks: The Role of Self-Concentration and Value-Non-Mixing in Attention**
  （arXiv 2609.09085）— StreamingLLM一脉将attention sink归因于RoPE等位置编码机制；本文通过因果掩码导致
  的"自我集中"与注意力输出的"value非混合"两个动力学角度重新解释sink成因，实证挑战"RoPE导致sink"这一
  广泛接受的解释，主张即使不用RoPE，自回归因果结构本身也足以产生sink；与9/9已收录的"Do New Attention
  Mechanisms Actually Fix Attention Sinks at Million-Token Context?"构成同一质疑线上机制归因层面的新
  数据点——若sink成因不是RoPE而是因果自我集中，StreamingLLM/H2O/SnapKV一脉基于"sink token可安全丢弃"
  的观测式eviction可能需要在因果结构而非位置编码层面重新校准。

### 📄 新论文（按 tier 分类，每条一行：标题 + 一句话 takeaway）

#### KV Cache 压缩/驱逐

- **BeaconKV**（arXiv 2609.04971）— 详见"今日必看"。
- **Jacap: Robust KV Cache Eviction via Jacobian-Based Nonlinear Information Capacity Preservation**
  （arXiv 2609.08131）— 把注意力过程建模为非线性高斯通信信道，推导Jacobian Information Capacity打分
  目标，与已收录的Random Attention（2609.03430，主张驱逐打分函数本身可能不重要）构成同批次相反方向的
  数据点——重新主张更精细的信息几何打分确实带来增益。
- **Grouped Value Attention: Efficient KV Caching via On-Demand Key Reconstruction**（arXiv 2609.13285）
  — 只存储分组后的value，用可学习线性映射按需重构content key，仅保留小型共享解耦RoPE通道承载位置信息，
  相比匹配的GQA配置持久化cache标量降低约45-47%；与已收录的VestigeKV（2609.03949）同属"解耦RoPE通道"
  母题的新变体，但落点是压缩cache布局本身而非驱逐打分。
- **Divergence Timing and Cumulative Disagreement under KV-Cache Eviction**（arXiv 2609.16617）— 用
  分布散度时序（而非终任务分数）量化SnapKV在50%保留率下比纯近期性基线更晚、更少进入分布散度状态，为
  "打分函数是否重要"这条争议线（Random Attention vs. 本文+Jacap）提供新的量化证据，支持精细打分确有价值。
- **It's Not RoPE that Creates Sinks**（arXiv 2609.09085）— 详见"今日必看"。

#### KV Cache 复用 / Position Re-indexing

- **CONDUIT: A Unified Residual-Stream Restoration Framework for KV Cache Reuse in Vision-Language
  Models**（arXiv 2609.05821）— VLM场景下训练无关地将单图/多图KV复用统一为"残差流恢复"框架，结合
  cached-key query attention与cached-value-norm代理打分排序待刷新视觉token；是CacheBlend一脉KV复用
  思路向VLM多模态场景的新扩展。
- **RedKnot-MLA: Multi-Head Offline-Online Reuse for DeepSeek-V4 Long-Context Serving**（arXiv
  2609.07008）— watchlist关注的RedKnot项目在DeepSeek-V4 MLA架构上的落地：离线预计算文档KV+query侧
  RoPE relocation做位置修正+仅对小规模Global-head集合在线重算，DeepSeek-V4-Flash配置下达到75.29%的
  分析可复用逻辑head-row理论上限；是CacheBlend一脉思路在MLA架构下的新实例。
- **Shared-Prefix KV Reuse Across Standard LoRA Adapters: Quality and Serving Tradeoffs**（arXiv
  2609.17109）— 研究KV复用的新维度：多个已训练LoRA专家共享同一backbone时，backbone的prefill KV cache
  只算一次并在专家间复用能保留多少任务质量、换来多少serving成本节省；是KV复用问题从跨请求/跨模型扩展到
  跨LoRA专家复用的新数据点。

#### Agentic Context 管理

- **Prefix Sharing Is a Sorting Problem**（arXiv 2609.13692）— 证明LLM serving中"固定全局排序"复用
  前缀片段（检索段落/工具定义/few-shot示例）的惯例仅在请求最多含两个片段时最优，给出结构定理将最小
  prefix-trie代价表示为请求上二叉层级结构的函数；工具定义被显式列为可复用片段之一，直接服务agentic
  tool-calling场景下的prefix排列优化，是对SGLang/Preble一脉prefix-aware调度背后排序假设的理论化推广；
  标记为tier_2边界情况——强KV机制贡献但"多智能体"框架较弱（单请求流内排序而非跨agent共享）。

### 🏗️ 工程/生态动态

- **vLLM**：新版本 **v0.29.0**（~9/9起，本轮核实到9/15后仍为最新稳定版）— prefix caching/调度侧新增
