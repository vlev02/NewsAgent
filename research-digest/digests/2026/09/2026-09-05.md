### 🔥 今日必看

- **Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning**（arXiv 2609.03430，Salesforce AI Research，9/3 挂出，[代码](https://github.com/SalesforceAIResearch/Random-Attention)）— 直接挑战 SnapKV/H2O 一脉"打分再保留 top-k"的核心范式：不计算任何重要性分数，只保留 prompt、在每个 attention head 内均匀随机驱逐,在 4 个模型 × 6 个推理任务上就打平最强的现有打分式驱逐方法,且在 vLLM 部署下吞吐还高 32%-43%；与已收录的 Trust the Mass（2608.25230，按权重保留已接近最优）、TwinKV（2608.27128，attention 幅度与因果贡献无关）、A Probabilistic Interpretation of KV Cache Eviction（2608.28293）构成同一批质疑"聪明打分函数"必要性的第四个数据点，且是迄今最激进的一个——不仅打分函数不重要，连打分本身可能都不需要。

### 📄 新论文（按 tier 分类，每条一行：标题 + 一句话 takeaway）

#### KV Cache 压缩/驱逐

- **VestigeKV: The NoPE-MLA KV Cache Carries Its Own Eviction Signal in a Vestigial Branch**（arXiv 2609.03949，9/3 挂出）— 指出基于观测 attention 的驱逐（H2O/SnapKV）在 NoPE MLA 模型上会失效（needle retrieval 0.00-0.33），因为 token 重要性在被查询前根本没被观测到；提出用 NoPE 训练后被重新征用为显著性通道的 64 维 RoPE 遗留分支（vestigial branch）作为查询无关的驱逐信号，只读每行 11% 的数据即可分层，标准配置下 128x 压缩仍保持 1.00 recall；与 Random Attention 同日挂出，构成"打分信号该从哪来"这一问题在 NoPE-MLA 架构（如 Kimi Linear）上的正面解法。
- **What Matters for Aggressive Decoding-Time KV Eviction? Temporal Aggregation and Ranking Preservation**（arXiv 2609.03515，9/3 挂出）— 指出现有 decoding 阶段 KV 压缩研究都聚焦设计更好的打分函数,却把"如何跨解码步聚合分数"这一时序规则当作实现细节；发现激进压缩下 EMA 聚合会让近似保序的打分函数改动在驱逐集合层面变得难以区分,据此提出 InertiaKV(EMA-based)及周期刷新变体 InertiaKV-Lazy(相对全量刷新提速 1.34-1.46x),并给出 Score-Free 变体(只在首个解码步打分一次、之后冻结排序,平均质量仅变化 +0.03)；把时序聚合规则和排序保持这两个此前被忽视的设计因子与打分函数本身并列为独立变量。
- **HeadWiseKV: Budgeted Per-Head Cache Residency for Hybrid Long-Context Language Models**（arXiv 2609.02029，9/2 挂出）— 针对混合架构模型（local/recurrent/linear attention 混合）里残差全局注意力层主导 KV 显存需求的问题,提出免训练框架 HeadWiseKV,给每个物理 KV head 分配静态、多档的历史窗口,使显存需求在 serving 前即可预测；将问题形式化为受限的 operational rate-distortion,SeqCalib 作为核心策略生成算法,112K 上下文下峰值显存降 8.59%,最大可验证成功上下文从 114K 拓展到 161K。

#### KV Cache 复用 / Position Re-indexing

- **CacheBridge: Efficient Cross-Model KV Cache Transfer**（arXiv 2609.00891，9/1 挂出）— 在已收录的 Cross-Model KV Cache Transfer(2608.03893,逐 head 闭式 ridge mapper)之上指出其 Full-Head Mapping 设计让每个目标 KV head 由所有源 KV head 共同映射,对架构差异敏感、且 mapper 存储/计算开销随支持层数增长；CacheBridge 改为每个目标 head 只匹配一个源 head、用因果 attention 敏感度加权重构误差、并用融合 GPU kernel 直接构造加权充分统计量而不物化完整观测张量,保持闭式仿射接口用于在线部署,目标端无需 prefill 或任务特定适配；与 2608.03893 构成同一"跨模型尺寸线性迁移 KV"问题的第二代改进。

#### Systems / Serving

- **mzCache: On-Device LLM Memory Management under Multitasking**（arXiv 2609.01338，9/1 挂出，基于 llama.cpp 实现）— 面向手机等移动 SoC 上的多任务场景:应用切换造成的内存压力会迫使操作系统驱逐 LLM 内存(含权重和 KV cache),新请求到来时必须走慢速存储读取或整段重算 KV cache,严重拖累响应速度；提出弹性驱逐 LLM 内存并利用移动 SoC 统一内存实现 GPU 侧零等待推理、同时 CPU 侧并发恢复,相比存储侧部分卸载基线 TTFT 降 2.1-5.5x；是 KV cache offload/驱逐机制在端侧多任务场景的新实例,与已收录的服务端 offloading 工作(CXL/CPU-GPU)构成同一问题在不同硬件层级的对应。
