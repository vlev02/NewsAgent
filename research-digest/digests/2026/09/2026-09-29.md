### 🔥 今日必看

- **[RFC] KV Context Editing — Relaxed Prefix Alignment for KV Reuse**（vLLM issue #58537，yxkyong，2026-09-24；https://github.com/vllm-project/vllm/issues/58537）— 提出 request-scoped 的 KV 层编辑接口 `vllm_xargs.kv_edit`：agent 在 **message 空间**（整条消息按全局 index + role 断言，或消息内字符 span）声明某些区间"语义已死"，明文保持 byte-stable，块哈希链不变，后缀 KV 原样复用，零重算；被编辑区间在 block table 中留 hole。关键设计取舍：**不做 position 压缩/重编号**（"renumbering would invalidate every downstream block"），后缀 token 保留绝对位置与 RoPE 相位，靠 masked attention 承担精度偏差；RFC 未引用任何学术论文。
  - 对 StructKV 的意义：**P3（协议与 SGLang 执行）** 的直接对标物——主流引擎首次出现"agent 声明 → KV 层原地编辑、不重发文本"的接口提案；同时回答接口边界调研的两个问题：(1) **ID 在哪层丢失**——该 RFC 用 message index + role 断言在请求层寻址、由 server 侧映射到 token span，说明 message 边界元数据需要显式跨层传递；(2) **StructKV 插入点**——`kv_edit` 的调用方（决定哪些 message 死）恰好是 StructKV 决策算法的输出位置。**P1（ReClaim）** 角度：它选择"留 hole 不 reindex"，与 prune+reindex 路线是对立设计，ReClaim 需要论证 reindex（压缩位置）相对 hole 方案在长程 agent 上的收益（位置 OOD / 块表碎片 / 注意力开销）与安全性。

### ⚠️ 竞品预警

- **vLLM RFC #58537 KV Context Editing**（见上）— 重叠点：agent 侧语义信号（哪些 message/tool result 已失效）驱动 KV 层原地编辑，不走文本重发、零 re-prefill，且是 message 空间的接口设计，直接落在 P3 执行侧。StructKV 剩余差异：(1) **决策侧**——RFC 只提供"调用方声明"的原语，不含从 episode 边界/工具调用状态/覆盖-重试-失败标记/依赖图推导剪枝决策的算法（P2 的 E1/E2/E3 仍无人占位）；(2) **物理回收 + 位置重索引**——RFC 只 mask 不 compact，显存/注意力开销仍在，且明确放弃 reindex（P1）；(3) 尚是 RFC（4 周反馈期），未见实现与评测数据。建议关注其后续讨论走向：若合入，StructKV 的 P3 需要以它为兼容目标而非另起接口。
- 核心竞品名单（Leyline / IntentKV / MemDecay / Beyond Compaction / TokenPilot / CodeComp / SmoothAgent / Stateful delta-only / SideQuest / Models Take Notes at Prefill）本轮按名称 + arXiv ID 搜索，**未检索到新版本或新的 follow-up**（arXiv 页面本轮无法直接抓取，版本号变化只能靠搜索结果侧面判断，可能有遗漏）。

- **vLLM RFC #58537**（见 🔥）— message 空间寻址 + role 断言的 KV 编辑请求面。对 StructKV 的意义：接口边界调研——message 边界元数据在 runtime→serving 路径上需要保留到 server，token span 映射由 server 侧完成（P3）。

### 📊 Workload 与证据

- **EfficientAgent: What Makes KV Cache Offloading Work for Concurrent Agents**（arXiv 2609.33762）— 同一 coding-agent workload 上 KV offloading 在不同部署下时快时慢时无效；关键变量是 host 层能否容纳整个 agent 池的"reuse working set"，用 stack-distance 模型估计并据此设定 host 层容量与写入策略。
  - 对 StructKV 的意义：**P1/P2 动机**——与 9/24 收录的 KVSET（2609.27746）同属"全量保留的容量不可行"证据簇；从另一侧说明为何要在 KV 层做结构化剪枝而不是单纯下放。
- **When Can Agents Forget Their Reasoning? ICLR for Long-Horizon Agent Context Compression**（arXiv 2609.29875，Mingxuan Wang 等）— 文本层、免训练：用 frozen proxy entropy 给 reasoning block 排序压缩，同时保留 action / tool call / observation；在 260 个 WorkBuddyBench 任务上 reward 0.699→0.718，input/output/cache-read token 分别降 25.5%/14.4%/33.3%。（信号来源类：按 deprioritize_exceptions 收录，因其区分了 reasoning 与 action/observation 的类型并报告 cache-read 变化。）
  - 对 StructKV 的意义：**P2 E1/E3**——"已外化状态后 reasoning 可遗忘"是一条可被 KV 层消费的类型信号（episode 内 reasoning 段 vs 动作段），可作为消融中"类型信号"这一档的候选；但它仍走文本重写，会触发 re-prefill。
- **KVCMAS: Efficient KV cache Correction for Shared Context in Multi-Agent Systems**（arXiv 2609.34060，Hyesung Jeon 等，KAIST 方向）— 用低秩状态表示跨 agent 的 KV 偏差并沿工作流链式修正，无额外 reference prefill；TTFT 2.0×，峰值显存较此前修正方法最多降 3.7×。
  - 对 StructKV 的意义：**P1**——"KV 原地修正而非重算"的又一个机制参照（修正对象是前缀差异，不是 prune 后位置），可作为 prune+reindex 之外的"近似修正"对照；非结构信号驱动，B 级。
