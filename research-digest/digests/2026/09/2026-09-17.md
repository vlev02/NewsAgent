### 🔥 今日必看

- **KVMem: Virtualizing Million-Token Agent Workspaces on a Consumer GPU**（arXiv 2609.04852，Di Chai/Leye
  Wang等）— 现有长程 agent 溢出历史管理多依赖文本摘要式压缩，本文把溢出历史保留为跨 GPU/host
  memory/NVMe 分页的 KV 状态，用模型原生 attention 空间索引按需拼出受限于原生上下文窗口的
  query-dependent 执行视图；DeepSWE 长上下文测试上 Qwen3.8-27B 任务成功率从压缩式基线的 43.8%
  提升到 48.4%，24GB 消费级 GPU 上可虚拟化 1M token workspace（原生窗口的 4 倍）；直接挑战
  "文本摘要压缩优于原始 KV 复用"这一假设，是 tier_2 核心命题（agentic 场景下落回 KV cache 管理）
  的有力正面数据点；9/4 挂出，距今 13 天但此前未收录，本轮补录。

- **Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read
  It**（arXiv 2609.18849，Yipeng Liu 等）— 现有 agentic serving 系统在工具调用执行期间靠猜测时长
  （按工具名/历史统计/声明时长/引擎占用率）决定是否保留、驱逐或重载该 agent 的 KV cache；本文主张
  工具调用应显式汇报真实进度，serving 系统读取该信号而非猜测；进度信号比已发表时长预测器准确好几倍
  到一个数量级，接入生产级引擎后相比 LRU 基线把工具调用后 p90 TTFT 降低约 20.7-20.8%，接近 oracle；
  直接挑战 tier_2/tier_4 现有工具调用间隙 KV 驱逐策略普遍依赖静态猜测这一惯例，是"agent 场景下落回
  KV cache 管理"这一方向的新范式；约 9/16-17 挂出，本轮 tier_2 检索新收录。

- **Contiguity, Not Importance: Budgeted Repair of Stale KV Caches After Document Edits**（arXiv
  2609.17983，COLM 2026）— CacheBlend/CacheClip 一脉 KV 复用隐含假设检索上下文/working
  memory/用户状态在会话中不变，但 agent 场景下这些内容会被中途编辑，导致缓存 KV 在编辑点之后整体
  过期；本文把过期修复形式化为预算受限重算问题，发现围绕编辑点的位置连续窗口（而非
  attention/重要性打分选择）效果最好，相比全量重新 prefill 加速 13-21 倍，恢复 0.94 的编辑后答案
  质量；是 KV cache 复用思路首次系统性扩展到"agent 运行中途编辑上下文/记忆"这一存活性问题，与
  已收录的 Bio-MemArt（9/13）、Forgetting Without Restarting（9/13）同属"KV cache 作为需要被主动
  管理的可变状态"这一新问题簇的最新成员；9/16 挂出，本轮 tier_2 检索新收录。

### 📄 新论文（按 tier 分类，每条一行：标题 + 一句话 takeaway）

#### KV Cache 压缩/驱逐

- **GroupKV: Hierarchical KV Cache Management for Long-Context Diffusion LLM Inference**（arXiv
  2609.17573）— 扩散语言模型(dLLM)的 block-wise 解码与周期性全序列重算使 KV 生命周期比自回归模型
  更动态；提出按生成 block 把上下文划为连续组做由粗到细的组级稀疏选择，配合跨层一致性预测性预取、
  staleness 校正与 streaming prefill；是已收录的 Fixed State, Long Reach（2609.11998，SSM 替代 KV
  cache 扩展到 diffusion LM）之外，dLLM 场景 KV 管理这条新兴分支上的第二个数据点，落点是分层稀疏
  选择而非状态空间模型整体替代；Jinhao Wang 等 5 人；**日期存疑**——检索到的摘要页信息显示提交日期
  为 7/30，与 arXiv 编号前缀 2609（按惯例对应 9 月）不一致，本轮按编号推断为 9 月新收录，留待下轮
  核实。

#### KV Cache 复用 / Position Re-indexing

- **Where Should the KV Cache Live? Placement Policies Across GPU, CPU, and SSD for Long-Lived
  Sessions**（arXiv 2609.16215）— 用离散事件仿真器（随机森林执行时间预测器校准）系统比较
  recency、复用频率、预测复用、EWMA+预取前瞻等策略，回答长期存活会话（多轮对话/agent/文档问答）
  下 KV block 该放 GPU HBM/CPU DRAM/SSD 哪一层、何时晋升/降级/驱逐/预取，对标 Mooncake/LMCache/
  FlexGen/InfiniGen/AttentionStore；**该 ID 昨日（9/16 digest）曾因 egress 限制未能定位到摘要而
  搁置为"疑似候选"，本轮经 3 个独立检索路径交叉确认为真实论文**，判断此前是索引延迟而非信息误
  组合；9/14 挂出，本轮补录。
- **Shared KV Caching for Replicated 27B Inference: Correctness Failures and Performance
  Boundaries**（arXiv 2609.15021，Frank Li，UNSW Sydney）— 在两个共享 256GiB LMCache 池的单 GPU
  27B vLLM 副本上做跨副本 KV 复用正确性审计，定位到一个遗漏当前 CUDA stream 依赖的裸指针回退路径
  缺陷（受控字节级测试在人为延迟下失败），修复后跨副本首字延迟中位数在 128k 输入下从 31.7 秒降到
  0.6 秒、256k 输入下从 92.0 秒降到 0.8 秒；挑战"跨副本 KV 复用只是简单内存共享工程问题"这一假设，
  揭示共享 KV cache 方案中容易被忽视的并发正确性风险；**同一 ID 昨日 digest 中也曾因摘要核实失败
  被搁置为疑似候选，本轮确认为真实论文并正式收录**；9/14 挂出。

#### Systems / Serving

- **Physically Partitioned KVCache Format for CPU–GPU Load Balancing in MoE Inference**（arXiv
  2609.14507）— 提出 InplaceKVCache，一种写入时即固定每字节物理归属（CPU 还是 GPU）的 KV cache
  字节布局，使负载 rebalance 无需搬运已放置数据；配合 WriteScope 用带在线反馈的 roofline 模型沿
  序列维度切分 CPU/GPU 份额；DeepSeek-V2-Lite/Qwen3-30B-A3B/Mixtral-8x7B、32GB 显存预算、最高 1M
  token 聚合上下文下相比复现的 vLLM/SGLang/KTransformers 类基线加速 1.4-2.5 倍；9/13 挂出。
- **FlexEE: Self-Speculative and KV-Compatible Early Exiting for Offloading-Aware LLM
  Inference**（arXiv 2609.17008，MICRO 2026）— 结合逐层退出监督、小型 top-K 本地词表上的
  self-speculative 解码降低退出决策开销，用动态 hidden state 管理保证 offloading 场景下的
  KV-cache-correct 执行；最高 1.27x/3.16x 层级加速、1.25x/2.83x 端到端加速；与已收录的 py-kvcache
  （9/11，NVMe offload connector）构成互补，一个做早退提速、一个做磁盘 IO；约 9/16-17 挂出。
- **JustFit: 200K-Token LLM Serving on a 24 GiB Laptop with Just-in-Time State Management**（arXiv
  2609.17475，Yuhua Chen）— 基于 MLX 的推理运行时，结合 KVExec（压缩 KV 执行）、PhaseSwap（组件
  驻留）、StateTrans（状态保持的 serving 转换）对 KV 状态做即时物化/释放，与权重量化正交；24GB
  M4 Pro 笔记本上跑 Qwen3.8-27B，单请求上下文从 30,720 扩展到 212,992 token（6.93 倍）；约
  9/16-17 挂出。
- **HBFlex: A Flexible Memory System for Bridging Fine-Grained LLM States and Coarse-Grained HBF
  Parallel Execution**（arXiv 2609.18675）— 面向用 High-Bandwidth Flash 承载动态 KV cache 的
  serving 场景，组合 KV 放置/访问均衡、写回聚合与基于生命周期的 block 打包+延迟回收，解决细粒度
  读取不均衡、写-读干扰、垃圾回收放大三个问题；索引显示约 9/16-18 挂出（可能因跨日时区显示为次日）。
- **Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches**（arXiv
  2609.17652，ICCAD 2026，代码已开源 vivekkalyanarangan30/fathom）— bit-plane channel-major 的
  4-bit KV cache 格式，让每个 query 通过对方差加权通道重要性做 reverse water-filling 自主挑选
  per-channel 读取深度；Qwen3-8B、1M token 上下文下比 Double Sparsity/Loki/SparQ(r=32) 快 1.67 倍
  解码步 GPU 时间；约 9/16-17 挂出。
- **ASPIRE: Asynchronous Batched Self-Speculative Decoding for Long-Context LLM Inference**（arXiv
  2609.17943，COLM 2026）— 取消同步 draft-verify 调度，引入统一混合前向传播、基于接受率估计的
  轻量在线逐请求推测调度器，以及 drafting 期间的 intra-draft 上下文刷新保持稀疏上下文时效性；
  **标记为 tier_1 边界情况**——speculative decoding 贡献强，KV cache 管理贡献相对弱（体现在上下文
  刷新机制而非 cache 存储/驱逐本身）；约 9/16-17 挂出。
