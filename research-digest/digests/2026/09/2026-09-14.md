#### KV Cache 压缩/驱逐

- **OmniKVQuant: KV Cache Quantization for Omni-LLMs**（arXiv 2609.11582）—
  现有KV cache量化方法（如KVQuant/TurboQuant）针对纯文本LLM设计，直接套用到Omni-LLM（音频/视频/文本混合输入）
  会遇到key的"时序漂移"和跨模态value几何异构两个新问题；提出训练无关框架，按输入流短时间窗口设定key量化范围、
  对不同模态分别做value旋转校正，在Qwen2.5-Omni/Qwen3-Omni上把KV cache压至2-bit且精度基本不损；是KV量化路线
  首次系统性扩展到多模态Omni-LLM场景；Suho Yoo等，约9/10-11挂出，本轮tier_0/tier_1双路检索新收录。
- **ECOKV: Geometry-Aware KV Cache Eviction via Complementary Diversity Metrics**（arXiv 2609.06663）—
  现有KV cache驱逐打分（H2O/SnapKV一脉）多依赖单一相似度/注意力指标刻画token重要性或冗余度；提出结合欧氏距离
  与余弦相似度的几何感知复合多样性度量，在与H2O/SnapKV相同的观测窗口设置下取得更优的压缩-精度权衡，同时降低
  峰值显存；是eviction打分函数设计这条线上的新变体，与近期一批审视打分函数可信度基础的工作（Trust the
  Mass/TwinKV/Random Attention）构成同批次但方向相反的数据点（仍主张更精细的打分有效，而非"打分本身可能不
  重要"）；9/6挂出，本轮watchlist（SnapKV/H2O关联检索）新收录，距今8天略超7天补录惯例窗口但因此前未收录且
  直接落KV层面，仍纳入。

#### KV Cache 复用 / Position Re-indexing

- **Fixed State, Long Reach: What a Constant-Size Cache Buys Block Diffusion at Scale**（arXiv 2609.11998）—
  扩散语言模型（diffusion LM）的双向去噪器天然无法使用标准自回归KV cache；提出block-causal训练目标，让
  mamba/attention/hybrid三种序列混合器将已完成block压缩为固定尺寸可复用状态，其中state-space版本缓存为
  O(1)（不随上下文长度增长），对比attention缓存的O(L)；3B模型、300B token预训练验证，256k上下文下相比
  attention缓存延迟降4.3x、显存降11x、单流吞吐提2.6x，8-16倍训练长度外检索能力仍保持而attention缓存2倍
  即崩溃；是SSM替代KV cache这条思路首次系统性扩展到diffusion LM serving场景，与已收录的Mamba/RWKV长上下文
  替代路线构成架构正交延伸（diffusion vs autoregressive）；ServiceNow Research/Mila，9/9挂出，本轮
  tier_0/tier_3联合检索新收录。
- **Content-Based Addressing for Long Context**（arXiv 2609.07314）—
  针对RoPE长上下文下的位置错配问题（训练时未见过的相对旋转偏移导致注意力失真），现有YaRN/位置插值类方法靠
  整体重标定位置区间来外推；提出将token流切成"单元"，单元内部保留常规RoPE位置，但为每个已完成单元分配一个
  由其内容（而非位置）计算出的地址，新单元复用同一学到的映射；保证局部RoPE精确不变，且插入/重排单元不改变
  已固定token对之间的注意力比较结果——这意味着KV cache中已算好的键值在上下文重组（RAG片段重排、多源拼接）
  后仍可复用而不必失效重算；是对YaRN/PI一脉"整体重标定位置"思路的结构性替代，直接服务于长上下文KV复用场景；
  Mahesh Godavarti（A Carrot, Inc.），9/7挂出，本轮tier_3检索新收录。

### 🏗️ 工程/生态动态

- **vLLM**：稳定版仍为v0.29.0（9/9），未发现新tag；但有两篇有实质内容的官方博客：
  - *Tiered KV Cache Offloading in vLLM*（2026-09-10）—— 详解自v0.22起提供的分层KV缓存卸载框架：被驱逐的
    KV数据统一先流经主机DRAM，再视情况下沉到文件系统、对象存储或远端peer节点（经RDMA/NIXL），命中时直接
    重载而非重算前缀，与LMCache的多级缓存思路相近，是vLLM原生KV offload connector的架构说明篇。
  - *Hybrid HiSparse Offloading for GLM 5.3*（2026-09-08）—— 针对稀疏MLA模型提出"压力驱动"的KV驻留策略：
    请求维护全驻留GPU/混合驻留/无驻留三种状态，GPU显存不足时释放最冷KV页面到主机内存而非抢占整条请求；
    8×H200、百万token上下文下并发请求数从5-6提升到19-25（约3-4倍），计划纳入v0.30。
  - PR #56492「Extensible KV cache」（draft，9/11更新）—— 用CUDA/ROCm虚拟内存管理预留设备地址空间、按需
    提交物理页，使KV缓存块可原地增长而无需搬迁基址，是对PagedAttention静态预分配块表模型的进一步演化。
- **LMCache**：稳定版仍为v0.5.5（9/12），仅有Intel XPU的rc7（9/12）与多平台nightly（9/14）小版本，未发现
  新的minor/major release；PR #5089「L1 Cache Move API」（open，9/13开出）—— 为多进程部署引入协调器托管
  的KV前缀"搬迁"API，将手动编排的"预取+删除"合并为一次原子化流程，支持同机P2P与跨机RoCE迁移。
- **SGLang**：稳定版仍为v0.5.19（9/5），未发现新tag；PR #39395「Improve usable prefix cache capacity with
  HiCache write-back」（open，9/14更新）—— 针对分层前缀缓存write-back批量加载占满host内存、误驱逐无关
  session数据的问题，新增按radix节点顺序加载的可选项，GB300实测可用token数提升51.5%、完整32K路径缓存命中率
  从61%提升到100%。
- watchlist具名项目（SnapKV/ChunkKV/H2O/CacheBlend/CacheClip/SideQuest/IntentKV/MiniPIC/MEPIC/CacheSlide/
  Attention Matching/Parrot/Preble/Autellix/InferCept）15项逐一检索：11项本轮无新论文/新release；SnapKV/H2O
  作为本轮三篇新论文（VestigeKV/Random Attention/ECOKV，前两者已在9/5收录）的对比基线被间接提及；MiniPIC与
  SideQuest的同名碰撞问题再次确认（分别对应HPC粒子模拟项目miniPIC、Claude Code编排工具Sidequest，均与
  KV cache/LLM无关）。
