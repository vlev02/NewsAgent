#### KV Cache 复用 / Position Re-indexing

- **MEPIC: Memory Efficient Position Independent Caching for LLM Serving**（arXiv 2512.16822，
  Qian Wang 等）— watchlist 长期缺口本轮补齐：这就是 7/30 digest 里标记"未能找到对应具体论文"
  的 MEPIC 条目。针对 deep-research/coding agent/RAG 场景下重复处理共享文档/代码 chunk 给 KV
  cache 带来的显存压力，把 chunk KV 对齐到分页存储、将重算粒度从 token 级降到 block 级（仅首块
  request-specific）、在 attention kernel 内通过 RoPE 融合直接去掉位置编码使其余块完全可共享；
  相比现有 position-independent caching 方案减少 HBM 里的重复 chunk KV 最高 2x（长 prompt 下
  达 5x），且不改动模型。2025 年 12 月已挂出，此前多轮遍历均未搜到，本轮补录。

#### Systems / Serving

- **HyMCache: A KV Cache Framework for Multi-Turn LLM Serving with CXL-Hybrid Memory**
  （arXiv 2607.18141）— 多轮 LLM serving 里 KV cache 复用要跨轮/跨 session 扩到 TB 级容量，但
  GPU HBM 和主机 DRAM 太贵撑不住；HyMCache 用 CXL-hybrid memory（小容量设备侧 DRAM 作 staging
  层 + SSD 背靠的大容量远程内存池）承载 KV，利用多轮访问读多、可预测、只追加的特点做请求级前缀
  预取和机会性写缓冲，在真实 CXL-HM 原型上、同等 DRAM 预算下 PD 分离 serving 场景相比本地
  LMCache 吞吐提升 3.0x。7 月中已挂出，此前几轮未搜到，本轮补录。
- **Robust KV Cache Management for LLM Serving under Output Token Length Uncertainty**
  （arXiv 2607.16892，Jiaming Cheng 等）— 指出 KV cache 显存必须在请求到达时就预留、但输出长度
  直到生成结束才知道：预留不足触发抢占式终止+重算，预留过多则浪费显存拖低吞吐；提出联合优化 GPU
  并行配置、按请求类别的 KV cache 预留、跨异构 serving group 的请求路由、以及共享 prompt 的
  prefix caching 的鲁棒管理框架。7 月中已挂出，此前几轮未搜到，本轮补录。
